EXP 13 – Prioritizing Online Learning Platform Requirements using MoSCoW and Kano in Jira

Aim:
To prioritize Online Learning Platform requirements using MoSCoW and Kano models and organize them in Jira.

Procedure:
1. Create or open a Jira project for the Online Learning Platform.
2. Add each requirement as a Jira issue/story.
3. Evaluate requirements using MoSCoW: Must, Should, Could, and Won't Have.
4. Classify requirements using Kano: Basic, Performance, Excitement, or Indifferent.
5. Record classifications in Jira issue labels, descriptions, or custom fields.
6. Arrange the backlog according to MoSCoW priority.
7. Review Must Have requirements for the initial release.
8. Save and verify the prioritized backlog.

MoSCoW:
Must Have – essential; Should Have – important; Could Have – desirable; Won't Have – deferred for this release.

Kano:
Basic – expected; Performance – more is better; Excitement – unexpected value; Indifferent – little effect on satisfaction.

Files:
- Other_Files/Online_Learning_Requirements.csv – Editable requirement table.
- Other_Files/Classification_Guide.txt – Priority/category definitions.
- Output/Prioritization_Matrix.png – Illustrative output.
- Screenshots/README.txt – Instructions for actual Jira screenshots.

Result:
Online Learning Platform requirements were prioritized using MoSCoW and Kano to define the release scope and backlog order.
