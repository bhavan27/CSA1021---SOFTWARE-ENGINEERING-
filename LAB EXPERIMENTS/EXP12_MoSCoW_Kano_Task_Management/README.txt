EXP 12 – Prioritizing Task Management System Requirements using MoSCoW and Kano in Jira

Aim:
To prioritize Task Management System requirements using MoSCoW and Kano models and organize them in Jira.

Procedure:
1. Create/open a Jira project for the Task Management System.
2. Add requirements as Jira issues (stories/tasks).
3. Assess each requirement using MoSCoW: Must, Should, Could, Won't.
4. Categorize each requirement using Kano: Basic, Performance, Excitement, or Indifferent.
5. Record priorities and Kano categories in issue descriptions, labels, or custom fields.
6. Arrange the backlog according to MoSCoW priority.
7. Review the prioritized backlog and select Must Have items for the initial release.
8. Save and verify the Jira backlog.

MoSCoW:
Must Have – essential; Should Have – important; Could Have – desirable; Won't Have – excluded from current release.

Kano:
Basic – expected necessities; Performance – more is better; Excitement – unexpected delight; Indifferent – little effect on satisfaction.

Files:
- Other_Files/Task_Requirements_Prioritization.csv
- Other_Files/Requirement_Classification_Guide.txt

- Screenshots/README.txt for actual Jira evidence.

Result:
Requirements were prioritized using MoSCoW and Kano to establish release scope and order the Jira backlog.
